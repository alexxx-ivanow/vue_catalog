# Техническое задание (промпт для разработки) — модуль «Интерактивные метки на фото» для 1С-Битрикс: Управление сайтом

## 1. Назначение и цель

Разработать модуль для «1С-Битрикс: Управление сайтом», реализующий функционал **интерактивных карт (меток) на изображении** — аналог существующего решения «Инфоград» (см. приложенную документацию). Модуль должен позволять администратору сайта загружать изображение-подложку, расставлять на нём кликабельные метки с координатами (в процентах), привязывать к каждой метке анонс/подробное описание/ссылку на товар, и выводить готовую интерактивную картинку на любой странице сайта через компонент.

**Область применения:** интернет-магазины (метки запчастей/деталей на фото товара), мебельные магазины (метки элементов интерьера), строительные компании (метки на схемах домов/этажей/квартир) и любые другие сценарии интерактивных карт изображений.

## 2. Архитектура данных

### 2.1. Инфоблок «Маркеры»
- Создаётся отдельный инфоблок (тип — многоуровневый, с произвольной глубиной вложенности разделов).
- **Разделы (Sections)** — иерархическая структура для группировки интерактивных карт (может быть произвольной вложенности, например: категория → подкатегория → карта).
- **Последний уровень раздела = «интерактивная схема»** — раздел, к которому привязана картинка-подложка и базовые настройки меток по умолчанию.
- **Элементы (Elements) внутри такого раздела** = отдельные метки с координатами и индивидуальными настройками (переопределяют настройки раздела).

### 2.2. Свойства раздела (интерактивная схема) — вкладка «Маркер»
| Поле | Тип | Описание |
|---|---|---|
| Название | строка | название карты, видно только в админке |
| Картинка-подложка | файл (jpg, png, svg, webp) | изображение, на котором ставятся метки |
| Основной цвет | цвет (HEX/RGB/HSL, с пипеткой) | цвет всех меток по умолчанию и кнопки «Подробнее» |
| Код для вставки на страницу | readonly, генерируется | `<div data-wnfgr="markers" data-id="{ID}"></div>` — альтернативный (вспомогательный) способ вывода без компонента |
| Иконка метки (svg) | файл .svg | кастомная иконка маркера по умолчанию |
| Размер иконки метки для ПК (px) | число | размер маркера на десктопе |
| Размер иконки метки для смартфонов (px) | число | размер маркера на мобильных |
| Цвет активной метки (hover/active) | цвет | цвет иконки при наведении/нажатии |

### 2.3. Вкладка «Визуальный редактор» (для раздела)
- Показывает загруженную картинку-подложку.
- По двойному клику левой кнопкой мыши по изображению создаётся новая метка (элемент) с координатами клика, пересчитанными в проценты от размеров изображения.
- Всплывающая мини-форма редактирования метки прямо на картинке: поля «Название», «Координата X, %», «Координата Y, %», кнопки «Сохранить» / «Удалить».
- Под изображением — таблица «Список меток»: Название (ссылка на редактирование элемента в новой вкладке) / Координата X, % / Координата Y, % / «К метке» (прокрутка карты и открытие метки визуально).

### 2.4. Свойства элемента (метки) — вкладка «Элемент»
| Поле | Тип | Описание |
|---|---|---|
| Заголовок метки | строка | название на сайте и в тултайпе |
| Координаты отметки по X, % | число (0–100, дробная часть до 2 знаков) | позиция по горизонтали относительно ширины изображения |
| Координаты отметки по Y, % | число (0–100) | позиция по вертикали относительно высоты изображения |
| Открывать только модальное окно | флаг Да/Нет | Да → клик по метке сразу открывает модальное окно (контент вкладки «Подробно»). Нет → клик открывает тултайп (контент вкладки «Анонс») |
| Цвет маркера | цвет #000000 | переопределяет цвет метки раздела |
| Цвет заливки маркера при наведении | цвет #000000 | переопределяет hover-цвет |
| Показать раскрытой | флаг | тултайп открыт по умолчанию (без клика) |
| Скрыть кнопку подробно | флаг | скрывает кнопку «Подробнее» в тултайпе |
| Надпись кнопки товара | строка | текст кнопки, заменяющей «Подробнее» |
| Цвет кнопки товара | цвет #000000 | |
| URL товара | строка (URL) | ссылка перехода при клике на кнопку товара |

**Логика приоритета кнопки товара:** кнопка «Купить товар» показывается вместо «Подробнее», если включено «Скрыть кнопку подробно» **или** не заполнено детальное описание на вкладке «Подробно».

### 2.5. Вкладка «Анонс» (контент тултайпа)
- Картинка для анонса (файл).
- Описание для анонса (текст / HTML / визуальный редактор).
- Два сценария вёрстки контента:
  1. Заполнено поле «Картинка для анонса» отдельно → на выходе: картинка сверху, текст (заголовок метки) снизу, кнопка «Подробнее» под ними.
  2. Поле «Картинка для анонса» пустое, картинки вставлены прямо в HTML-описание → порядок и расположение текста/картинок определяется вручную через HTML/визуальный редактор.

### 2.6. Вкладка «Подробно» (контент модального окна)
- Детальная картинка (файл).
- Детальное описание (текст / HTML / визуальный редактор), поддержка списков, изображений и т.д.
- Контент выводится в модальном окне при клике на метку (если включена опция «Открывать только модальное окно») либо по кнопке «Подробнее» из тултайпа.

## 3. Компонент вывода на странице

Реализовать компонент **`myApp:markers`** (шаблон `.default`) со следующими параметрами:

```php
$APPLICATION->IncludeComponent(
    "myApp:markers",
    ".default",
    array(
        "IBLOCK_ID"          => #IBLOCK_ID#,
        "SECTION_ID"         => #SECTION_ID#,
        "SORT_BY1"           => "NAME",
        "SORT_ORDER1"        => "ASC",
        "SORT_BY2"           => "ID",
        "SORT_ORDER2"        => "DESC",
        "CACHE_TYPE"         => "A",
        "CACHE_TIME"         => "3600000",
        "COMPONENT_TEMPLATE" => ".default",
    ),
    false
);
```

- В настройках компонента (в режиме правки страницы / «эрмитаж») должен быть выбор конкретной «интерактивной схемы» из выпадающего списка («Доступные интерактивные карты»), формируемого по названиям разделов последнего уровня.
- Поддержать настройки кеширования (авто + управляемое, время кеширования).
- Дополнительный упрощённый способ вставки — копирование готового HTML-сниппета `<div data-wnfgr="markers" data-id="{ID}"></div>` с автоматической инициализацией JS по data-атрибуту (для пользователей без навыков работы с компонентами Битрикс).

## 4. Фронтенд-логика (JS/CSS)

1. **Рендер меток:** абсолютное позиционирование маркеров поверх изображения по `left: X%; top: Y%;`, где X/Y — сохранённые координаты (адаптивность должна сохраняться при любом размере контейнера).
2. **Адаптивность иконок:** применять разный размер иконки метки для десктопа и для мобильных (брейкпоинт по ширине экрана/viewport, значения — из настроек раздела «Размер иконки метки для ПК/смартфонов»).
3. **Состояния метки:** обычное / hover / active — переключение цвета заливки согласно настройке «Цвет активной метки» (на уровне схемы) с переопределением на уровне метки.
4. **Тултайп:**
   - открывается по клику на метку (или сразу, если «Показать раскрытой»);
   - содержит заголовок, анонс-картинку и/или HTML-описание анонса;
   - кнопка «Подробнее» (или кнопка товара — см. логику приоритета в п. 2.4) — открывает модальное окно или переходит по URL товара;
   - при «Скрыть кнопку подробно» — кнопка не выводится (если нет URL товара — кнопки нет вовсе).
5. **Модальное окно:** открывается либо напрямую по клику на метку (если включено «Открывать только модальное окно»), либо по кнопке «Подробнее» из тултайпа; содержит детальную картинку и HTML-описание из вкладки «Подробно»; закрытие по крестику/клику вне окна/Esc.
6. **Иконки меток:** поддержка кастомной SVG-иконки (заливка через `currentColor`/CSS-переменную, чтобы можно было управлять цветом через настройки), либо иконка по умолчанию (геолокационный пин).
7. Все цветовые настройки (`Основной цвет`, `Цвет активной метки`, `Цвет маркера`, `Цвет заливки маркера при наведении`, `Цвет кнопки товара`) должны применяться через инлайн-стили/CSS-переменные, генерируемые на сервере при рендере компонента.

## 5. Админ-панель

1. **Основные свойства** — стандартная форма редактирования раздела инфоблока (вкладка «Маркер») с полями из п. 2.2, загрузкой файлов через стандартный файловый диалог Битрикс + drag&drop, цвет-пикер (RGB/HSL/HEX + «пипетка», аналог штатного JS color picker).
2. **Визуальный редактор** — отдельная вкладка на форме раздела, реализованная как JS-виджет:
   - вывод превью картинки-подложки в масштабе;
   - обработка double-click → создание нового элемента (AJAX-запрос на создание элемента инфоблока с проставленными координатами) с открытием мини-формы редактирования прямо на картинке;
   - drag существующей метки мышью — обновление координат (желательно, но не критично для MVP; в базовой версии — редактирование координат только числом);
   - таблица списка меток под картинкой с AJAX-обновлением при добавлении/удалении/переименовании.
3. **Форма элемента (метки)** — стандартные вкладки инфоблоков Битрикс: «Элемент» (свойства из п. 2.4), «Анонс», «Подробно», плюс штатные SEO/Реклама/Разделы.
4. Числовые координаты: целая часть (0–100) регулируется вводом с клавиатуры и стрелками up/down; дробная часть (1–99) — только вводом с клавиатуры (реализовать через JS-маску/валидатор на поле).

## 6. Нефункциональные требования

- Совместимость: 1С-Битрикс: Управление сайтом (последняя стабильная версия ядра D7), PHP 7.4+/8.x.
- Модуль оформить как самостоятельный модуль с `install/index.php`, регистрацией событий, языковыми файлами (`ru`/при необходимости `en`), и стандартной структурой `components/`, `lib/`, `install/`.
- Хранение настроек — через UF-поля (пользовательские свойства) разделов/элементов инфоблока либо через свойства инфоблока (property), без изменения ядра.
- Кеширование вывода компонента — управляемое кеширование Bitrix (композитный кэш допустим).
- Адаптивная вёрстка (мобильные, планшеты, десктоп), поддержка touch-событий вместо hover на мобильных устройствах.
- Безопасность: экранирование HTML-описаний при выводе (разрешить безопасный HTML из визуального редактора, фильтрация XSS), проверка прав доступа в административной части.
- Логирование ошибок через штатный `CEventLog`.

## 7. Приёмочные сценарии (для тестирования)

1. Создание раздела «интерактивная схема» с загрузкой картинки-подложки — успешно, поле «Код для вставки» генерируется автоматически.
2. Добавление 3+ меток через визуальный редактор двойным кликом — координаты сохраняются корректно и совпадают с положением клика.
3. Ручной ввод координат через форму элемента — метка визуально перемещается на нужное место при выводе на сайте.
4. Переключение «Открывать только модальное окно»: Да → клик открывает модалку; Нет → клик открывает тултайп.
5. Проверка двух вариантов вёрстки анонса (картинка отдельно vs. картинка внутри HTML-описания).
6. Проверка отображения кнопки товара вместо «Подробнее» при выполнении условий п. 2.4.
7. Проверка адаптивных размеров иконок на десктопе и мобильном устройстве.
8. Проверка вывода через компонент `myApp:markers` с выбором конкретной карты из списка и через альтернативный `data-wnfgr` сниппет.
9. Проверка кеширования — изменение метки должно сбрасывать/обновлять кэш вывода.
